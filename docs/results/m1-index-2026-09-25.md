# M1 index exit demo — 2026-09-25

Repository: `django/django`, commit
`a3d71038401b9340f550f2fdf1caaad66465ba88` (stable/5.2.x at measurement).
Machine: Apple M1, macOS, Python 3.11 in the project virtual environment.
Embeddings were disabled. The initial fresh index used a shallow checkout with
one Git commit. We then deepened it to 200 commits to check the Git miner.

Fresh checkout and index:

```sh
git clone --depth 1 --branch stable/5.2.x https://github.com/django/django.git django-m1
git -C django-m1 fetch --depth 1 origin a3d71038401b9340f550f2fdf1caaad66465ba88
git -C django-m1 checkout a3d71038401b9340f550f2fdf1caaad66465ba88
mog index --repo django-m1 --json
mog index --repo django-m1 --json
mog search Model.save --repo django-m1 --json
git -C django-m1 fetch --deepen=199 origin stable/5.2.x
mog index --repo django-m1 --json
```

After fetching 199 more commits, an unchanged-source index refreshed Git history
in 2.44 s and produced 44 directed `co_changed` edges. A subsequent `--full`
rebuild with that history took 29.06 s; the database was 128,004,096 bytes
(376% of indexed source). The following unchanged index took 1.75 s. Full
rebuild includes deleting and rewriting the existing graph, so it is slower
than an initial index into an empty database.

The original full-index run with the former FTS table took 19.16 s and occupied
145,821,696 bytes (429% of indexed source). The v3 contentless FTS table removes
the duplicate stored previews. Migrated databases are compacted once with VACUUM.

This is an M1 exit measurement, not a retrieval quality benchmark. M2 still
requires B0/B1 comparisons on pinned real-refactor corpora.
