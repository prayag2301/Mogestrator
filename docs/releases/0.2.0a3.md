# Mogestrator 0.2.0a3

Moved or renamed symbols now leave their anchored memories stale with a wording-review warning. Anchor continuity is preserved, but a matching code body no longer silently validates memory text that may name the old path or symbol. Retrieval and MCP remain experimental; the M2 quality gate remains open.

## Changes

- Preserve the original anchor in memory metadata when following a unique rename. Keep memory text, provenance, and pins intact.
- Keep the review warning visible through recall, memory search, verification, re-indexing, and server restarts.
- Return immediately from memory search when no memories exist, avoiding source reads and graph traversal.
- Guide MCP clients to use search, expansion, memory lookup, and verification selectively instead of requiring a session-start ritual.
- Publish the recorded Claude and Codex agent-session comparisons, including negative results. No new agent-efficiency claim is made for this release.

## Validation and limitations

The implementation passed 137 tests across local runs, lint, version checks, and the installed-package smoke test. Real MCP clients exercised stdio and loopback HTTP, write restrictions, watch refresh, and moved-memory warnings across restart.

Moves processed by older versions did not retain original anchors and require manual memory review. Even a memory whose wording remains correct is conservatively marked stale after a move. Record a reviewed fact against the current symbol; automatic correction or supersession is not implemented.

Install with `pip install --pre "mogestrator[mcp]==0.2.0a3"` or `uvx --from "mogestrator==0.2.0a3" mog`.
